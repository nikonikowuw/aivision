# 人员注册与索引引擎

## Goal

为父任务 `08-26-person-management` 提供 C++ 侧人员注册和 1:N 候选索引能力：对有界注册图片执行质量检测与特征提取，基于完整有效特征快照构建候选索引，并以不会中断旧索引服务的方式原子激活新版本。

## Requirements

- 定义正式的 Go/C++ gRPC 契约，覆盖注册图处理、稳定质量错误、候选索引构建、激活、废弃、状态查询和重启恢复。
- 算法包清单必须声明特征提取器 ID/版本、模型内容摘要、预处理契约、输出维度与数据类型、归一化方式、相似度度量和 `feature_contract_id`；平台按规范化字段与实际模型文件 SHA-256 重算契约，声明不一致时拒绝安装或加载，注册处理结果回传不一致时拒绝该结果。
- 注册图必须且只能包含一张满足质量门槛的人脸；成功结果返回图片 ID、质量结果、特征字节、生产算法包身份、特征提取器身份、模型摘要和 `feature_contract_id`。
- 所有图片和特征载荷必须有明确大小上限，不进入常规运行消息或日志。
- 新索引构建期间旧索引继续服务；候选索引只有在完整构建后才能原子激活。
- 提供统一索引刷新协调能力，将已完成特征准备的单人员操作和业务批次提交组合并为候选版本，避免每个人员分别重建全量索引。
- 业务批次提交组不可拆分；协调器按可配置数量阈值或最早提交组最长等待时间触发刷新，大型业务批次最多参与一次全量构建。
- 阈值按平台 Profile 管理：先在 Apple Silicon macOS 实测冻结开发参数，RK3576 验收前独立实测，通用协调器不得硬编码平台数值。
- 业务批次在全部索引项完成特征准备或终止后才进入就绪队列，最长等待从就绪时开始计算。
- 支持显式从候选索引移除人员的人脸特征；移除后旧照片和特征版本的业务保留由 Go 控制面决定。
- 同一候选版本中的人脸变更作为原子组激活；构建或激活失败时整组不生效，不能暴露部分索引结果。
- 单人员索引变更通过持久化异步作业驱动；引擎调用超时或进程重启后必须能够按操作状态对账，不能假定原 HTTP 连接仍存在。
- 暂时性引擎不可用在同一操作内按上层退避策略最多重试 3 次；引擎命令必须幂等，使重试不会创建并行候选索引或重复激活。
- 普通注册处理以图片 SHA-256、`feature_contract_id` 和质量策略版本形成指纹；生产算法包版本仅记录为来源，不参与兼容性去重。相同人员相同指纹的成功结果不得重复提取或加入索引刷新，强制重提取明确绕过该规则。
- 支持强制重新提取模式：基于已有注册照片重新执行质量检测与特征提取，不因指纹命中已有成功结果而短路；新特征只在候选索引成功激活后替换旧版本。
- 强制重新提取的处理范围、目标算法包版本和算法激活计划相互独立；单人、选中和全量范围都执行真实目标提取，目标可为当前、候选或可加载历史版本。失败时只有匹配当前激活 `feature_contract_id` 的旧特征可继续服务。
- 支持针对固定人员快照的全量特征迁移，目标算法身份与 `feature_contract_id` 必须显式记录；旧算法、旧特征和旧索引在迁移期间共同保持激活。
- 当前、候选和可加载历史算法包版本都可作为全量强制提取目标；初始快照和追平增量中的每张当前照片都必须在目标版本下真实提取。只有关联明确升级或回切计划的全量任务完成后才可触发算法、特征和索引原子激活。
- 算法包版本切换是否要求全量迁移只由 `feature_contract_id` 兼容性决定：契约相同可复用现有特征，契约不同必须先完成全量迁移；包版本号不同不能单独作为失效依据。
- 引擎算法包运行时默认保留已安装历史版本；当前激活、候选或任务引用版本必须持有可查询的运行引用，删除检查不能依赖调用方猜测。历史包重新安装后按首次安装标准重新校验契约与模型摘要。
- 新算法安装后仅创建候选算法版本；在迁移和候选索引构建期间，不切换激活算法或改变旧特征的可用状态。
- 引擎只允许与当前激活算法包所要求 `feature_contract_id` 匹配的特征进入激活索引；生产该特征的算法包版本可以不同，只要契约兼容。旧特征可为审计或回切保留，但契约不匹配时必须失效且不得参与搜索。
- 全量迁移以有界并发准备特征，并仅在准备阶段结束后构建一次完整候选索引；不得按人员重复执行全量索引构建。
- 候选版本满足激活条件后，目标算法、目标特征集合和完整候选索引按同一版本原子激活；任一构建或激活步骤失败时继续使用完整旧版本。
- 人员级质量或提取失败不视为候选算法构建失败；引擎基于所有成功的目标契约特征构建完整候选索引，并返回被排除人员清单供控制面确认。
- 无论是否存在人员级失败，只要控制面提交的成功特征完整快照通过算法契约、候选索引构建和版本一致性校验，引擎均支持直接原子激活；算法加载、契约、索引构建或切换失败时不得激活。
- 若最终完整快照对应的控制面水位仍有注册照片但目标特征集合为空，引擎不得激活空索引并返回稳定迁移验证错误；控制面明确声明当前无注册照片时允许激活合法空索引。
- 最终写屏障前失败人员照片变化时，引擎仅为该人员重新执行目标算法处理并更新候选特征；已成功候选特征按版本复用，不重新执行全量提取。激活后的换图按当前算法普通处理。
- 控制面在最终激活前按数据库变更水位提交追平后的最新完整特征快照；引擎不得自行复用早期人员快照，删除、移除或换图后的旧特征不能进入最终候选索引。
- 最终写屏障期间，引擎以幂等版本号构建并激活一次追平后的完整候选索引；原子切换完成前继续服务旧索引。
- 目标算法、目标特征快照与目标索引属于同一激活版本，禁止新查询特征算法与不兼容的旧底库特征同时生效。
- 确定性质量失败可按相同指纹复用，暂时性运行故障不可缓存为图片永久失败。
- 构建、激活或通信失败不得破坏当前激活索引；重复命令必须具备明确的幂等语义。
- 支持 10,000 人完整特征快照，并记录构建耗时、峰值内存和切换行为。

## Acceptance Criteria

- [ ] 合格单脸图片返回可持久化的质量、特征和特征契约结果；无脸、多脸及各质量失败返回稳定错误码。
- [ ] 10,000 人候选索引构建期间，识别持续使用旧索引且无部分新数据可见。
- [ ] 一个业务批次包含多个人脸变更时不会被拆成多个候选索引版本，并可与其他就绪提交组合并刷新。
- [ ] 数量未达阈值时在最长等待时间内必定触发刷新，达到阈值时无需继续等待；重启后就绪提交组不会丢失或被重复提交。
- [ ] macOS 与 RK3576 Profile 可使用不同阈值，切换配置不改变 gRPC、索引版本或业务结果契约。
- [ ] 显式移除人脸并激活候选索引后，该人员不再参与搜索，其他索引成员不受影响。
- [ ] 批次候选索引失败时该批全部人脸变更不生效，旧激活索引保持完整可用。
- [ ] 单人员异步操作期间旧索引持续服务，成功后原子切换，失败或重启恢复不会产生半激活版本。
- [ ] 同一操作的引擎命令重试可安全对账，不重复构建已存在候选版本或重复切换激活版本。
- [ ] 相同注册处理指纹复用成功或确定性失败结果；图片内容或任一契约版本变化时重新执行完整注册流程。
- [ ] 单人、选中和全量强制重提取都绕过成功指纹复用；目标可选当前、候选或可加载历史版本，失败时仅有与当前激活契约匹配的旧特征保持有效。
- [ ] 只有关联明确升级或回切计划的全量任务可触发算法切换；普通强制提取任务无论目标版本和范围如何都不会擅自改变当前算法。
- [ ] 算法包版本变化但特征契约相同时现有特征保持兼容；模型摘要或任一契约字段变化时产生新 `feature_contract_id`，不兼容目标激活前必须执行全量迁移。
- [ ] 篡改模型文件、遗漏契约版本更新、清单声明错误或运行时回传契约不一致均被稳定拒绝，不会产生错误标记为 `ready` 的特征。
- [ ] 引擎能准确报告算法包的激活、候选和任务运行引用；被引用版本删除失败且不中断任务，无运行引用历史版本删除后不影响已持久化特征来源记录。
- [ ] 10,000 人全量迁移可恢复、进度可查询且只构建一次完整候选索引；激活前识别始终使用匹配的旧算法与旧特征空间。
- [ ] 候选算法安装和迁移不会提前改变激活算法或旧特征可用性；激活后算法身份、特征契约和索引版本一致切换。
- [ ] 人员提取失败不会丢弃已成功的候选特征或阻止候选索引自动激活；激活索引只包含成功人员的目标契约特征，失败人员的旧契约特征不会混入。
- [ ] 迁移初始快照之后发生的新增、换图、移除和删除经控制面追平后反映在最终完整快照中；引擎激活的索引版本与该最终水位一致。
- [ ] 候选一致性校验通过时支持自动原子激活，不以人员级失败作为阻塞条件；系统级构建或切换失败时旧激活索引保持不变。
- [ ] 最终水位有注册照片而目标特征集合为空时拒绝激活并保留旧索引；控制面证明最终水位无注册照片时可激活空索引。
- [ ] 最终写屏障前单个失败人员换图只重算其目标特征；任务激活后的换图按当前算法生成新候选索引变更，均不影响其他成功特征。
- [ ] 新索引原子激活后状态查询返回一致版本；失败或重启后仅恢复最后一个已激活版本。
- [ ] gRPC 契约、大小边界、幂等语义和错误映射均有自动化契约测试。

## Out of Scope

- 人员业务表、HTTP API、管理前端和 RBAC。
- 人脸模型精度研发与人员资料字段定义。

## Blocking Open Questions

无。
