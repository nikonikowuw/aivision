# 人员管理前端与集成验收

## Goal

为父任务 `08-26-person-management` 交付面向管理员的人员管理界面，并验证从照片提交、质量反馈、特征与索引激活到删除停止识别的完整用户闭环。

## Requirements

- 新增“资源管理 -> 人员管理”，路径 `/resource/person`、路由名 `ResourcePerson`、页面权限 `resource:person`。
- 人员管理页提供受 `resource:person:sync-config` 控制的“同步设置”入口，用于维护 IP/CIDR 白名单，不新增独立菜单。
- 人脸能力挂载在人员档案详情中：从人员列表进入详情后完成补录、换图和移除人脸，不新增独立的人脸管理菜单、页面或路由。
- 姓名修改、补录、换图和移除人脸统一受 `resource:person:update` 控制，不拆分独立人脸按钮权限。
- 新增、编辑、删除分别受 `resource:person:create`、`resource:person:update`、`resource:person:delete` 控制；权限同时约束按钮可见性和接口访问。
- 人员管理页提供只读“同步记录”视图，不新增独立菜单；复用人员页面查看权限，展示批次提交时间、来源 IP、状态和数量汇总。
- 同步记录支持按时间范围和批次状态筛选；进入批次详情后可按 `person_id`、项目状态分页定位失败阶段、稳定错误码、错误原因和可重试标识。
- MVP 同步记录不提供整批重试、回滚或修改原批次结果的操作；纠错仍通过新的人员同步请求完成。
- 人员表单只展示 `person_id`、姓名和当前人脸照片，不加入部门、联系方式、分组或标签控件。
- 新增表单允许选填 `person_id`，留空时由服务端生成；字段旁明确提示创建后不可修改，编辑页面只读展示该值。
- 姓名为必填项但不做重名拦截；列表和详情始终同时展示 `person_id`，避免把同名人员误认为同一人。
- 页面和前端 API 不展示或依赖数据库内部 `id`，人员详情及操作使用业务主键 `person_id`。
- 管理员通过本地文件选择提交 JPEG/PNG，提交前可预览；页面不要求输入图片 URL，也不使用通用上传组件先生成公开文件地址。
- 新增时照片可选；页面根据派生字段 `has_face` 显示是否已有当前人脸照片，并独立显示 `feature_status`，支持按“未注册人脸”“有照片但未提取”“特征可用”“特征已失效”等状态筛选。
- 页面将建档与人脸注册作为连续但独立的步骤；照片失败时保留已建档人员，停留在可重试的补录状态。
- 删除操作不提供恢复入口；删除后可用相同 `person_id` 重新建档，但页面不得复用或暗示恢复旧照片。
- 已注册人脸的人员提供独立“移除人脸”操作；执行后保留人员并显示“未注册人脸/未提取”，编辑姓名不得隐式清除照片。
- 已注册人脸的人员详情提供“重新提取特征”，复用当前照片且不要求再次上传；操作需二次确认并展示异步进度，未注册人脸人员不显示或禁用该操作。
- 人员列表支持勾选批量和一键全量重新提取；三种范围使用同一强制提取语义。目标版本可从当前、候选及设备仍保留且可加载的历史算法包中选择，确认界面展示目标算法包、特征提取器/契约和影响人数。
- 页面将“强制提取”和“算法升级/历史回切”明确分开：普通提取不会切换全局算法；只有关联升级或回切计划的全量任务会在完成后激活目标版本。若目标契约与当前契约相同，页面说明无需全量迁移但仍允许用户主动强制提取。
- 历史算法版本列表默认保留并显示可加载状态；管理员可显式删除无运行依赖版本。激活、候选或任务引用版本禁用删除并说明原因，仅有历史特征来源引用时允许删除但明确提示之后无法使用该版本提取。
- 全量任务页面展示总进度、成功/失败数量和分页逐项失败，不因离开页面而中断；已有全量任务运行时禁止重复发起并引导查看现有任务。
- 候选算法迁移期间页面明确区分“当前激活版本”和“候选目标版本”；迁移任务未激活前，人员列表继续展示当前线上特征状态，不提前显示为 `stale`。
- 全量迁移存在人员失败时仍自动激活新算法；页面展示失败人数、逐项原因和这些人员已暂时退出识别的结果，不提供“确认部分激活”步骤。
- 部分成功的候选算法激活后，失败人员显示“特征已失效”，并提供换图和重新提取入口；成功人员不重复处理。
- 全量迁移在候选一致性校验通过后自动激活，页面只展示激活进度与 `activated|activated_with_errors` 结果，不弹出第二次确认。
- 最终写屏障前，失败人员换图直接关联当前迁移任务；任务已经激活后，从失败明细换图或重新提取将创建当前新算法下的普通异步操作。
- 最终仍有注册人脸但成功特征数为 0 时，页面显示迁移验证失败和旧算法仍在服务，不得误报新算法已激活；没有注册人脸时允许展示空索引激活成功。
- 全量任务将初始快照进度与迁移期间待追平增量分开展示；人员正常维护不因长时间迁移被禁用，只有最终激活的短暂写屏障期间提示稍后重试。
- 页面不展示或提交人员版本字段；同字段并发修改以后一次成功请求为准。
- 补录、换图、移除人脸和删除当前可识别人员提交后展示异步处理中状态并轮询 `operation_id`；不得因 HTTP 已接受就提前显示成功。
- 处理期间继续展示旧稳定人脸状态，最终成功后刷新人员，失败后展示可重试原因并保留原状态。
- 收到 `PERSON_OPERATION_IN_PROGRESS` 时展示现有操作进度并恢复轮询，不重复提交或在前端自行排队。
- 若组合操作只完成人员资料但人脸注册失败，页面明确展示“资料已保存、人脸未更新”并支持重试。
- 提供人员分页查询、筛选、新增、编辑、换图、删除和详情查看，并使用现有类型化 API 层与 RBAC 按钮权限。
- 照片提交必须展示上传进度、处理中状态和稳定质量错误，不得在 API 尚未完成索引激活时显示成功。
- 列表页启用路由缓存；重新激活时刷新数据并保留筛选、分页和滚动位置。
- 菜单、页面和错误文案遵循项目国际化要求，不混淆“人员”与“后台用户”。

## Acceptance Criteria

- [ ] 有权限管理员能完成合格人员的新增、修改、换图、删除和查询，无权限用户不能通过菜单或直接 URL 访问。
- [ ] 表单拒绝空姓名但允许重名；同名人员以 `person_id` 清晰区分，编辑或删除不会作用到另一名同名人员。
- [ ] 新增时手工 `person_id` 可成功保存，留空可获得服务端生成值；重复值显示明确冲突且不会进入照片处理状态。
- [ ] 不合格照片显示可操作的明确错误；换图失败后页面仍展示旧有效照片。
- [ ] 超过 10 MiB 或非 JPEG/PNG 文件在前后端均被拒绝，合法文件提交后进入异步处理状态。
- [ ] 首次照片注册失败后，人员仍在列表中显示为“未注册人脸”，管理员可直接重试补录。
- [ ] 无照片建档成功后明确提示“未注册人脸”且不暗示可识别；人脸注册成功提示出现时人员已经参与识别，删除成功时人员已经停止识别。
- [ ] 页面在 10,000 人数据规模下使用服务端分页，不一次性加载全部记录或照片。
- [ ] 移除人脸与删除人员是两个明确区分的操作，并使用不同确认文案和权限动作。
- [ ] 管理员无需离开人员管理即可在指定人员详情中维护人脸；系统中不存在可脱离人员档案操作的独立人脸列表。
- [ ] 具有 `resource:person:update` 时可编辑姓名并维护人脸，缺少该权限时相关入口均不可用且直接调用接口也被拒绝。
- [ ] 重新提取特征会进入可轮询的异步状态；成功后刷新人员特征版本，失败时页面明确提示旧特征仍在使用。
- [ ] 一键全量可覆盖任务开始时全部已注册人脸人员，并持续展示跨页面、跨重启进度；任务不会对每个人员触发一次完整索引构建。
- [ ] 一键全量可选择当前、候选或可加载历史版本，均不提供“复用旧特征”选项；页面明确提示生产提取器、`feature_contract_id` 及本任务是否关联算法切换。
- [ ] 选择算法包版本时页面根据 `feature_contract_id` 显示“特征兼容/需要全量迁移”，而不是仅根据算法包版本号判断；模型或契约变化时不能绕过全量迁移要求。
- [ ] 算法包契约校验失败时，历史/候选目标不可选择，并展示稳定错误；页面不能允许管理员绕过清单、模型摘要与平台重算指纹不一致的问题。
- [ ] 历史版本不会自动消失；删除入口准确区分运行依赖和仅审计引用，删除后版本从提取目标中移除但既有特征来源仍可查看，重新安装并校验成功后恢复可选。
- [ ] 页面根据 `has_face` 展示当前人脸照片是否存在，并独立展示特征状态；不依赖单独的 `face_status`。特征契约过期时显示“特征已失效”并停止暗示该人员仍可识别。
- [ ] 候选算法迁移期间页面继续按当前激活版本展示人员可识别状态，并单独展示目标版本和迁移进度；原子激活成功后才切换到新契约状态。
- [ ] 全量迁移存在人员失败时仍自动激活；管理员看到准确影响人数和失败明细，失败人员显示为有照片但特征失效，并可直接换图或重新提取。
- [ ] 迁移期间发生的人员人脸变化显示为独立增量追平进度，不改写初始总数；最终写屏障返回可重试错误时页面不误报保存成功，并可让管理员重新提交。
- [ ] 无失败和存在人员失败的迁移都自动激活且不重复确认；页面刷新或重新登录后仍能查看 `activated_with_errors` 的失败明细并修复人员。
- [ ] 最终写屏障前可从失败明细换图并在原任务内看到重试结果；任务激活后同一入口改为发起当前新算法下的普通换图或重新提取操作。
- [ ] 页面能区分零成功保护失败与合法空图库激活，并准确展示当前仍在服务的算法版本。
- [ ] 同步设置只对有权限用户可见，可维护 IPv4/IPv6/CIDR 并在保存后立即影响外部同步请求。
- [ ] 两个页面会话修改同一字段时以后一次成功写入为准；异步人脸操作完成时不会覆盖期间更新的姓名。
- [ ] 页面离开再返回后仍能恢复未完成操作的轮询状态，并正确展示最终成功或失败结果。
- [ ] 有人员页面权限的管理员可查询只读同步记录和逐项失败结果；无 `resource:person:sync-config` 权限仍可查记录但不能查看或修改白名单设置。

## Out of Scope

- 抓拍、识别记录、Top-K 候选和 Webhook 页面。
- C++ 模型、索引和 Go 数据事务实现。

## Blocking Open Questions

无。
