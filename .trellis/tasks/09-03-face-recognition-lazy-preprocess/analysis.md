# 预处理彻底废除全图 RGB 优化总结分析报告

> 任务编号：`09-03-face-recognition-lazy-preprocess`  
> 责任模块：`algo-packages/macos/arm64/face_recognition`  
> 关联规范：`.trellis/spec/engine/runtime-guidelines.md`  
> 硬件环境：Apple M4 (10 Cores, 4P+6E), 24GB Unified Memory, macOS 26.5.1  

---

## 1. 优化背景与根因

在消除了 SCRFD 9-Head 5 ms 拷贝开销后，分析发现**全分辨率 RGB 转码与缩放（4K 6.85 ms / 1080P 1.48 ms）**成为了主视频流最大的性能瓶颈与堆震荡源。

经全链路代码追踪证实：
1. SCRFD 模型仅需要固定 $640 \times 384$ 的 Letterbox 图像；
2. GLINTR 特征提取模型仅在确认抓拍帧需要 $112 \times 112$ 的特写人脸；
3. Engine 端录像与图片抓拍异步直接使用原生解码帧写盘，算法包从不持久化或导出全图 RGB；
4. 全图 RGB 纯粹为早期从 Python/OpenCV 原型直译迁移而来的历史包袱。为截取 1.2 万像素（占 4K 全图 0.15%），每帧无脑转码 830 万像素，产生每帧 14.5 MB ~ 58.1 MB 的无效堆震荡。

---

## 2. 优化方案设计与实施

1. **彻底废除全分辨率 RGB/ARGB 堆分配 (0 MB Heap Churn)**：
   - 从 `PreprocessResult` 与预处理管线中彻底移除 `original_rgb` 与 `temp_argb`，单帧巨额堆分配彻底清零。
2. **NV12 直接硬件分级降采样 (Direct Fast Letterbox)**：
   - 直接利用 Apple Accelerate vImage 硬件指令集：
     - Y 平面：使用 `vImageScale_Planar8` 直接从原图尺寸降采样至目标视口（如 $640 \times 360$）；
     - UV 平面：使用专门针对 2 通道交织色度平面的 `vImageScale_CbCr8` 直接硬件降采样至 $(320 \times 180)$；
   - 仅对缩放后的 23 万像素执行色彩转换，写入常驻且预填 114 中性灰的 640x384 缓冲，像素转码量相比 4K 减少 **36 倍**。
   - 所有中间缩放缓冲使用 `thread_local` 常驻工作区，零单帧堆分配。
3. **NV12 双平面直接五点仿射对齐截脸 (`align_face_112x112`)**：
   - 仅在触发特征提取时，基于 5 关键点求逆相似变换矩阵，直接在 NV12 的 Y 连续平面与 UV 交织平面上分别做双线性插值并即时计算 BT.709 色彩转换输出 112x112；
   - 单次截脸耗时仅需 **16 微秒 (0.016 ms)**，非提取帧开销彻底为 0。
