# 彻底废除全图 RGB：零冗余直出 640x384 与 112x112 预处理优化

## Goal

彻底消除 `face_recognition` 算法包中全分辨率 RGB/ARGB 的历史遗留转码与堆内存分配（1080P 14.5 MB，4K 58.1 MB）。
1. 输入 NV12 直接降采样并生成 SCRFD 所需的 640x384 Letterbox RGB（计算像素量减少 36 倍）；
2. GLINTR 特征提取所需的 112x112 对齐人脸特写直接从 NV12 的 Y/UV 平面按需双线性插值采样（仅需计算 12,544 像素点）；
3. 彻底消除全尺寸原图的色彩空间转换与每帧巨额堆分配，将 4K 预处理耗时由 6.85 ms 压缩至 1.0 ms 左右，吞吐突破 200+ FPS；1080P 预处理耗时由 1.48 ms 压缩至 0.3 ms 左右，吞吐达到 350+ FPS。

## Background & Root Cause

1. 经过对整个算法包、SDK、Engine 及 Go 后端全链路追踪证实：**生产业务根本不需要全分辨率 RGB**。
   - SCRFD 人脸检测仅需固定的 640x384 灰色填充图（737 KB）；
   - GLINTR 特征提取仅需固定的 112x112 仿射对齐脸图（37 KB）；
   - 全景图与特写图抓拍由 Engine 异步直接使用解码器原始帧编码落盘，算法包从不导出也不持久化全图 RGB。
2. 现有代码每帧无条件将整张 4K 原图（8,294,400 像素）转为 33.2 MB ARGB 再转为 24.9 MB RGB，白白浪费 6.85 ms（占整帧 73.5%），纯粹是为了从 830 万像素中截取 1.2 万像素（0.15%）的历史原型直译包袱。

## Requirements

### R1. 彻底废除全尺寸 RGB/ARGB 内存分配 (0 MB Full-Frame Heap)
- 从 `PreprocessResult` 与预处理管线中彻底移除 `original_rgb` 与 `temp_argb` 全图缓存；
- 单帧运行期间彻底消除每帧 14.5 MB (1080P) / 58.1 MB (4K) 的巨额堆内存反复分配与释放。

### R2. NV12 直接快速 Letterbox 降采样 (Direct Fast Letterbox)
- 输入无论是 Host NV12 还是 CVPixelBuffer，直接将 Y 平面与 UV 平面降采样至目标视口尺寸（如 16:9 下为 640x360），仅对这 23 万像素执行色彩转换，写入常驻的 640x384 灰色 114 填充缓冲，直接消除 36 倍无效像素计算。

### R3. NV12 双平面直接五点仿射对齐采样 (Direct 112x112 NV12 Sampling)
- `align_face_112x112` 直接基于 5 关键点求得的逆相似变换矩阵，在 NV12 的 Y 连续平面与 UV 交织平面上分别做双线性插值并即时转换为 RGB 像素；
- 仅在确认触发特征提取时按需计算 12,544 像素点（耗时 < 0.04 ms），非提取帧耗时为 0。

### R4. 纯 C ABI 与精度对齐
- 保持外部公共 C ABI 契约不变；
- 保持 SCRFD 检测坐标与置信度完全对齐；
- 保持 112x112 截脸输出的人脸特征向量提取行为正确稳定。

## Acceptance Criteria

- [ ] 1080P `best_shot` 场景预处理耗时降至 <= 0.5 ms，总 FPS 达到 >= 330 FPS。
- [ ] 4K `best_shot` 场景预处理耗时降至 <= 1.5 ms，总 FPS 达到 >= 200 FPS。
- [ ] 单帧全分辨率 RGB/ARGB 堆分配彻底归零（0 MB）。
- [ ] 算法包单元测试、ABI 测试与 ASan 内存检测 100% 通过。
- [ ] 边界纯洁性与全工程回归测试 100% 通过。
