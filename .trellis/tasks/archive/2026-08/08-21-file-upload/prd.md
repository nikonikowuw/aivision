# 添加文件上传接口

## Goal

为后台提供统一的文件上传 HTTP 接口，并将文件保存能力抽象为可替换的存储接口，使业务层不依赖具体存储实现，能够按配置使用本地文件系统或 MinIO。

## Confirmed Facts

- 后端使用 Gin、分层的 API Handler/Service 结构，并通过 google/wire 装配依赖。
- 所有业务 API 位于 `/api` 下，默认经过认证和权限中间件；统一响应格式为 `{code, data, message}`，成功码为 `0`。
- 前端共享请求客户端已提供 `requestClient.upload`，会将数据编码为 `multipart/form-data`，业务 API 应放在 `ui/apps/web-antd/src/api/core/` 下。
- 当前仓库没有现有上传模块、文件存储配置或 MinIO 依赖。

## Requirements

- 新增文件上传接口，接收 multipart 表单中的文件，并返回前端可直接使用的文件元数据及访问地址。
- 定义与具体存储无关的文件存储接口；API/Service 仅依赖该接口，不直接调用本地文件或 MinIO SDK。
- 提供本地文件存储实现和 MinIO 存储实现；通过配置选择实现，不修改业务调用方。
- 在服务端限制上传大小，校验空文件和非法文件名，避免路径穿越及文件名冲突；错误通过项目现有 errno/统一响应机制返回，不泄露内部错误细节。
- 增加后端接口、两种存储实现和配置的测试；若添加前端 API 封装，则保持类型安全并复用现有 `requestClient`。
- 更新 Swagger 文档和必要的配置示例，记录上传字段、响应结构、认证要求及存储配置。
- 上传接口要求登录；上传成功返回可直接访问的文件地址。该访问地址不再要求 Bearer 认证：本地实现通过受控静态路径提供，MinIO 实现通过配置的公开地址提供。持有地址者可访问文件，地址不得包含用户原始文件名或敏感信息。
- 上传成功应记录操作日志，但 multipart 内容不得写入日志；沿用现有日志中间件的截断/脱敏行为，并为上传路由注册语义化 i18n action。

## Acceptance Criteria

- [ ] 已认证用户使用 multipart 字段 `file` 调用 `POST /api/file/upload`，可以获得 `code=0` 的文件元数据和可直接访问的 URL。
- [ ] 空文件、超过 `10 MiB` 限制的文件、扩展名或实际内容类型不在 `jpg/jpeg/png/gif/webp/pdf` 范围内的文件，以及无法安全处理的文件名被拒绝，并返回统一错误响应。
- [ ] 切换存储配置后，业务上传接口无需改动即可使用本地或 MinIO 实现。
- [ ] 本地存储写入的文件可按返回地址读取；存储失败不会返回成功响应，也不会留下可继续使用的半成品文件。
- [ ] 存储接口、两种实现和 HTTP Handler 均有覆盖核心行为的测试。
- [ ] 上传接口要求认证，但成功返回的 URL 可直接访问；返回 URL 不包含原始文件名或敏感信息。
- [ ] 上传成功应记录语义化操作日志，multipart 文件内容不写入操作日志。
- [ ] `go test ./...`、`go vet ./...` 通过；如包含前端 API 改动，`pnpm check` 通过。

## Decisions

- 同时实现本地文件系统和 MinIO 两种存储，使用配置选择实现；业务 API/Service 只依赖统一存储接口。
- 上传接口为 `POST /api/file/upload`，multipart 字段名为 `file`，所有已认证用户可调用，不额外要求角色权限。
- 响应返回原始文件名、对象 key、文件大小、实际内容类型和可直接访问的 URL；对象 key 使用随机生成值，避免路径穿越、重名覆盖和原始文件名泄露。
- 本地文件通过后端静态路径提供，MinIO 通过配置的公开 URL 前缀提供；MinIO bucket 的公开访问策略由部署配置负责。
- 首版文件类型限制为 `jpg/jpeg/png/gif/webp/pdf`，默认单文件上限为 `10 MiB`；服务端按文件内容和扩展名双重校验。
- 上传失败统一映射到 errno 错误码；内部存储错误只记录服务端日志，不向客户端返回底层错误详情。
