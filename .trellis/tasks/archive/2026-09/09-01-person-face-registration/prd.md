# 人员人脸注册与多脸管理

## Goal

在现有人员管理模块中增加人脸注册能力，使一个人员可以绑定多张独立的人脸样本，并由现有 `face_recognition` 算法包提取统一格式的特征向量，为后续人员识别和特征库同步提供可靠数据基础。

本任务需要明确注册入口、特征提取调用边界、样本与向量的持久化方式、重复人脸处理以及人员/样本的生命周期；不改变现有人员基础信息 CRUD 的兼容行为。

## Confirmed Facts

- `argus/internal/model.Person` 当前只有 `personId` 和 `name`，没有人脸样本或特征关联模型。
- `face_recognition` macOS 算法包已有 SCRFD 人脸检测、112x112 对齐和 GLINTR 512 维 L2-normalized `float32` embedding 流程。
- 现有识别结果使用 `AV_RESULT_RECOGNITION`，embedding 以 little-endian `float32` 原始字节的 Base64 字符串出现在结果 JSON 中。
- `engine/proto/argus/v1/person.proto` 目前只有预留的 `SyncPersons` RPC，没有注册图像或特征向量契约。
- 前端人员页面目前只提供人员基础信息分页、创建、编辑和删除。
- 后端已有可替换的 `FileStorage` 抽象和 multipart 文件校验能力，但尚未定义人脸样本元数据表。
- 现有 `09-01-main-stream-face-recognition` 任务把管理端页面、向量检索和人员注册列为范围外，因此本能力单独规划。
- 注册流程已确定为：Go 接收并校验管理端上传图片，通过 `engine.sock` 调用专用特征提取 RPC，Engine 返回受约束的 embedding。
- 图片跨进程采用有界 unary gRPC `bytes` 传输，不传绝对路径、不依赖 Go/Engine 共享文件系统、不使用 Base64 传输图片；local 与 MinIO 存储实现对上层保持透明。
- 每个人员最多保留 10 个未删除人脸样本；已删除样本不计入上限，删除后可继续注册。
- 注册图片必须落盘保留，用于人工对比；不能在特征提取成功后直接丢弃。
- 每个人脸样本同时保留原始注册图和 112x112 标准化人脸图；两者均通过样本专属的受保护访问接口提供，删除时执行成对清理。
- 人脸图片不直接复用当前公开 `/uploads/` 访问语义，需要样本专属的受保护存储、访问和删除逻辑，并与特征样本建立关联。
- 每次上传的图片必须且只能包含一张合格人脸；无人脸或多张人脸时拒绝请求，不提供本期内的多人脸选择交互。
- 注册质量门槛复用现有算法包默认值：人脸检测分数不低于 `0.50`、人脸短边不低于 `40 px`、综合质量分数不低于 `35/100`；Engine 负责最终判定。
- 注册图片压缩后的请求体不超过 `10 MiB`，解码后的宽高不超过 `3840x2160`，总像素不超过 `8,294,400`；后端和 Engine 均执行边界校验。
- 对原始上传字节计算 SHA-256；同一文件再次绑定到任意人员时拒绝。本期不按 embedding 相似度拦截近似重复人脸。
- 样本创建后不可替换；需要更新时先删除旧样本，再重新注册。
- 具有人脸样本管理权限的管理员可通过 Bearer 鉴权接口查看或下载原始图和标准化图；接口不生成公开 URL，图片响应以内联方式返回。
- 本任务接入特征提取并持久化结果；实时特征库同步和视频识别匹配留到后续任务。


- 人员与人脸样本应为一对多关系；每个样本有稳定标识、所属 `personId`、特征模型/维度/数据类型等元数据和生命周期状态。
- 注册流程必须验证输入图片中存在且适合注册的人脸，并通过受支持的算法包提取 embedding；不能由前端伪造向量作为可信特征。
- 公开人员接口应能查看和管理样本摘要，但不应无必要地返回原始 embedding。
- 删除人员、删除样本和重复提交的行为必须具有明确且可测试的幂等/一致性语义。
- 管理端人员页面应能完成新增样本、查看样本数量/摘要和删除样本等核心操作。
- 特征格式、大小上限、模型版本和算法不可用时的错误映射需要在 Go、Engine/IPC、算法包和前端之间保持一致。

## Open Questions

- 无。实现边界和主要产品规则已确认，技术细节记录在 `design.md`。

## Acceptance Criteria

- [x] 规划阶段明确注册输入、提取调用路径、数据保留、容量和重复策略。
- [x] 实现后一个人员可以创建并独立删除多个人脸样本，现有人员 CRUD 不回归。
- [x] 注册请求只能保存由受支持算法包成功提取且通过校验的 embedding。
- [x] 后端、IPC/Engine、数据库和前端契约具有对应测试与错误映射。

## Constraints

- 生产数据库结构变更必须使用新的版本化 migration；SQLite 内存库仅用于单元测试。
- 特征向量属于敏感生物识别数据，日志、普通列表和错误响应不得泄露原始向量或内部异常细节。
- 复杂任务在 `task.py start` 前必须补齐 `design.md` 和 `implement.md`，并通过规划评审。
